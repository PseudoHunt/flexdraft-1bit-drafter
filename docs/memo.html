A 1-bit FlexDraft drafter keeps 91% of its acceptance length

Drafter FlexDraft-Qwen3-8B · target Qwen3-8B Quantizer NanoQuant ADMM, full-covariance objective Metric τ, accepted tokens per drafting step, GSM8K test, greedy Code + all results github.com/PseudoHunt/flexdraft-1bit-drafter

The drafter's forty attention projections go from 800 MiB to 56 MiB at 1.13 bits per weight and retain 91.3% of the FP drafter's τ. The target and the post-calibrator are untouched, so output quality is unchanged by construction. The goal was 95%. The last four points came from changing what ADMM minimises, not from tuning — and that is where the remaining gap most likely lives too.

Method

  1. Covariance-weighted ADMM. NanoQuant's binary factorization W ≈ diag(s₁)·S_A·S_B·diag(s₂), ranks 2016 (q/o) and 800 (k/v), but minimising output error under the real input covariance, ‖(W − AB)·L‖, LLᵀ = Σ, instead of NanoQuant's diagonal approximation. Same alternating structure; the B-step becomes an exact Sylvester solve. The drafter's inputs have effective rank ≈ 700 of 4096, so the diagonal was discarding most of the structure — this step alone halves held-out output error and is worth +0.87 τ before any tuning (t = 6.4). Costs 3.4× NanoQuant's ADMM time, about eight minutes.
  2. Residual base. A second factorization of W − Ŵ₁ at rank 256/96 with the same objective, +0.13 bpw.
  3. Target-as-teacher tuning. Plain cross-entropy between the drafter's mask-token logits and the target's greedy tokens, on contexts the target itself generated. NanoQuant's own refinement (MSE against the FP drafter) recovers 4% of the gap; the target as teacher recovers 35–41% on the diagonal init and a further +0.22 on the covariance init. The FP drafter is not the ground truth — the target is, and it's already running.

What moved τ

  • ADMM objective: full input covariance instead of its diagonal +0.87 at init, t = 6.4; +0.34 after tuning, t = 2.7
  • Teacher = target instead of FP drafter +0.34 → +0.78, t = 4.7–7.4
  • On-policy calibration windows (the drafter had been tuned on text it never sees; FP prefill-τ 3.6 off-policy vs 10.8 on-policy)
  • Calibrated i_norm at init +0.47, t = 7.2
  • Residual base at init +0.42, t = 7.2 — erased by tuning

What did not (paired t over 40 prompts)

  • Acceptance-weighted loss vs plain CE t = 0.2
  • Tuning latents vs scales vs both t = 0.7; latent LR to 3e-4 t = 1.5
  • 4× more calibration data t = 0.5
  • Budget-neutral rank reallocation q→o, k→o |t| ≤ 0.7
  • Group-128 scales −1% weight error, not run
  • Fine-tuning the FP post-calibrator t = −0.7
  • Hadamard input rotation t = −3.5, hurts
  • Top-256 soft-label KD t = −0.1; early stopping t = −0.9
  • Output-side weighting (o_norm) from the target loss t = −1.2

Where the last four points came from, and what 95% would take

Every tuning-side change — objective, data, parameterisation, capacity, the post-calibrator, soft labels — left the drafter fitting its calibration windows better than the FP drafter (prefill-τ 12.2 vs 10.8) while unseen windows sat at 9.0. That plateau moved only when the factorization itself got better: with the covariance objective, held-out sits at 9.4 and τ at 91.3%. The lesson for the remaining 3.7 points is that the quantization objective, not the tuning stage, is the lever with headroom. Three directions are open, none in the current budget:

Read with care. Weights are simulated in bf16: this measures the 1-bit representation's accuracy, not kernel speed. Single seed, 40 GSM8K test prompts, block 16, confidence threshold 0.01. FlexDraft's fused-QKV path can't run on quantized modules; all comparisons use the unfused path (FP 7.312) except the per-projection and allocation ablations (fused, FP 7.101). The FP post-calibrator is 164 MiB — three times the binarized drafter. Covariance ADMM is validated bit-for-bit against NanoQuant when Σ is diagonal; its transposed variant is numerically unreliable at the real condition numbers (≈4·10³) and is not used. Setup notes worth knowing: the released checkpoint's config key dflash_config doesn't match the code's flexdraft_config; NanoQuant's package has a circular import.
